# SmartExpense(모으다) — 모임 관리시스템 개발 정의서

| 항목 | 내용 |
|------|------|
| 문서 버전 | 1.0 |
| 작성 기준 | 현재 코드베이스 (`com.smartexpense`) |

| 대상 범위 | 모임 허브 · 회원 · 회비 · 장부 · 경조 · 결산 · 설정/클라우드 |

---

## 1. 문서 목적

본 문서는 SmartExpense Android 앱의 **모임(동호회) 관리시스템**에 대한 개발 정의서이다.  
제품 목적, 역할·권한, 화면/업무 흐름, 데이터 구조, 핵심 비즈니스 규칙을 코드 기준으로 정리하여 이후 개발·운영·인수인계의 기준 문서로 사용한다.

---

## 2. 제품 개요

### 2.1 목적

동호회·모임의 **회원 명단, 회비, 입출금 장부, 경조사비, 연간 결산**을  
기기 로컬(Room)과 Firebase(Auth/Firestore) 클라우드로 관리한다.

### 2.2 주요 사용자 시나리오

1. 로그인(Google 또는 이메일) 후 **모임 허브**에서 소속 모임을 선택한다.
2. 신규 사용자는 **모임 찾기 → 가입 요청 → 관리자 승인 → 회원정보 입력** 후 입장한다.
3. 기존 명단 회원은 **초대(이메일/UID)** 또는 승인 후 **동일 이름 명단을 수정·연결**한다.
4. 모임 내부에서 회원·회비·장부·경조·결산을 조회하며, 관리자는 편집·클라우드 동기화·초대를 수행한다.

### 2.3 진입 구조

```
인증 게이트 → 모임 허브(Meeting Hub) → 모임 메인(Club Main)
  ├ 회원
  ├ 회비
  ├ 장부
  ├ 경조
  └ 결산
      └ 설정(계좌·이력·클라우드·초대·운영관리자 지정 등)
```

## 4. 역할·권한 정의

앱 **로그인 권한**과 **회원 명단 직책**은 분리한다.

### 4.1 앱/모임 권한

표시 우선순위: **시스템관리자 > 모임관리자 > 일반회원**

| 역할 | 판정 기준 | 주요 권한 |
|------|-----------|-----------|
| 시스템관리자 | 허용 이메일(allowlist, 앱·Firestore 규칙 동기) | 전체 모임 관리, 위험 작업. **회원 명단에 등록되지 않음** |
| 모임관리자(개설자) | `meetings.ownerUid` | 운영관리자 지정, 편집, 동기화, 삭제, 초대 |
| 운영관리자(지정) | `meetings.adminUid` | 편집, 동기화, 초대(편집 권한 범위) |
| 일반회원 | `meetings.sharedWith` 포함 | 조회 위주. 쓰기는 관리자만 |

권한 플래그 개념:

- `canEdit` / `canSync`: 개설자·지정 운영관리자·시스템관리자
- `canAccessCloud`: 소속 회원 포함(조회)
- `canDangerousOps`: 시스템관리자(초기 이행·위험 삭제 등)

### 4.2 회원 명단 직책(장부상)

| 직책 코드 | 표시 |
|-----------|------|
| GENERAL | 일반 |
| PRESIDENT | 회장 |
| TREASURER | 운영관리자(명단 표시) |
| EXECUTIVE | 임원 |

※ Firestore `adminUid`(앱 운영 권한)와 명단 `role`은 별개이다.

## 5. 인증·세션·보안

### 5.1 인증

- Google 로그인 및 이메일/비밀번호 로그인
- 회원가입(이메일) 지원
- 시스템관리자: 전용 로그인 경로(고정 자격증명, 클라이언트 설정). Gmail 계정 비밀번호로는 불가 안내
- 로그인 후 `userProfiles/{uid}` 미완이면 프로필 입력 게이트
- 휴면 회원 등: `MemberLoginPolicy`로 로그인/입장 제한

### 5.2 미활동 세션

| 항목 | 값 |
|------|-----|
| 미활동 타임아웃 | 10분 |
| 연장 안내 | 60초 카운트다운 |
| 미연장 시 | 자동 로그아웃 |
| 상호작용 | 터치 시 타이머 리셋(경고 중 제외) |

연장 승인 시 즉시 타이머를 리셋하며, 디스크에 오래된 활동 시각으로 덮어쓰지 않는다.

### 5.3 앱 잠금

- PIN / 패턴 / 생체: **계정(이메일)별** 등록
- 허브 설정에서 등록·변경. (잠금 전용 풀스크린은 설정 맥락에 따름)

## 6. 모임 허브(Meeting Hub)

### 6.1 탭 구성

| 탭 | 설명 |
|----|------|
| 내 모임 | 소속·개설·지정관리·승인대기·회원정보 미입력 모임 |
| 모임 찾기 | 공개 디렉터리 검색 후 가입 요청 |
| 가입 대기 | 관리 모임의 가입 요청 승인/거절 |
| 만들기 | 신규 모임 생성(개설자=본인) |

시스템관리자: 「내 모임」이 전체 모임 성격으로 확장될 수 있다.

### 6.2 가입·승인·입장

```
가입 요청(PENDING)
  → 관리자 승인(APPROVED, profileCompleted=false, sharedWith 추가)
  → 회원정보 입력(명단 등록/수정, profileCompleted=true)
  → 모임 입장
```

| 상태 | UI 표현(예) |
|------|-------------|
| PENDING | 승인 대기 |
| APPROVED + 프로필 미완 | 회원정보 입력 |
| APPROVED + 프로필 완료 / ACTIVE | 일반회원 등 역할 배지 |
| 휴면·탈퇴(제한) | 활동 중지 |

거절(REJECTED)·철회(WITHDRAWN) 후 재요청 가능.

### 6.3 모임 생성

- 생성자 = `ownerUid`, `sharedWith`에 본인 포함
- `meetingDirectory`에 검색용 게시
- 개설자 회원 자동 등록(시스템관리자는 명단 등록 스킵)

## 7. 회원 생명주기

### 7.1 상태

| 상태 | 표시 | 요지 |
|------|------|------|
| ACTIVE | 활동중 | 정상 이용 |
| DORMANT | 휴면 | 로그인·해당 모임 입장 불가. `sharedWith` 제거, inactive 기록 |
| WITHDRAWN | 탈퇴 | 로그인은 가능, 해당 모임은 재가입 요청 필요 |

개설자·지정 운영관리자는 회원 상태와 무관하게 입장 가능.  
개설자/지정 운영관리자의 자발 탈퇴·강제탈퇴는 지정 해제 등 선행 조건이 있다.

### 7.2 강제 탈퇴

- 회원 **문서 삭제**
- 접근 정보 **완전 제거**(sharedWith / inactive 정리)
- 관련 가입 요청 삭제
- 이후 「모임 찾기」에서 다시 가입 요청 가능  
※ 단순 ‘탈퇴(WITHDRAWN)’ 유지와 다름

### 7.3 초대 공유

설정 → **모임 공유하기**

| 상황 | 처리 |
|------|------|
| UID 또는 이미 로그인 이력(프로필/명단 연결/가입요청) | `sharedWith`에 즉시 추가, 명단 `linkedUid` 연결 |
| 명단에만 있고 미로그인 | `invitedEmails`에 예약 → 동일 이메일 로그인 시 자동 합류(claim) |
| 신규(명단 없음) | 「모임 찾기」가입 요청 유도 |

### 7.4 회원정보 입력(이름 기준 upsert)

초대 또는 가입 승인 후 본인이 회원정보를 등록할 때:

1. **계정( UID / 이메일 ) 일치** 명단이 있으면 → 해당 문서 **수정**
2. 없으면 **동일 이름** 명단이 있으면 → 해당 문서 **수정·계정 연결**
3. 둘 다 없으면 → **신규 등록**
4. 동일 이름이 **다른 계정에 이미 연결**된 경우 → 덮어쓰지 않고 오류 안내

날짜 필드(가입년월일·생년월일 등): **숫자 키보드 직접 입력** + 달력 선택 병행.

## 9. 데이터 구조

### 9.1 Firestore

| 경로 | 용도 |
|------|------|
| `meetings/{meetingId}` | 모임 메타, ownerUid, adminUid, sharedWith, inactive*, invitedEmails, 잔액, 회비납부방식 |
| `meetingDirectory/{meetingId}` | 검색용 공개 목록 |
| `meetings/{id}/members/{docId}` | 회원 명단 |
| `meetings/{id}/transactions/{docId}` | 장부 |
| `meetings/{id}/dues/{docId}` | 회비 |
| `meetings/{id}/accounts/{docId}` | 계좌 |
| `meetings/{id}/eventExpenses/{docId}` | 경조사비 |
| `meetings/{id}/histories/{docId}` | 이력 |
| `meetings/{id}/joinRequests/{docId}` | 가입 요청 (collectionGroup 조회) |
| `userProfiles/{uid}` | 앱 사용자 프로필 |

규칙 요지(`firestore.rules`):

- 로그인 사용자: meetings get/list
- 생성: owner=본인, sharedWith에 본인 포함
- 수정: 모임 관리자 또는 자가 탈퇴/초대 claim/제한된 self 키
- 하위 컬렉션 쓰기: 관리자(회원 self-enroll·이름 연결 update 예외)

### 9.2 Room(로컬)

클럽·회원·회비·거래·경조·이력·계좌·설정 등 로컬 미러/오프라인 지원.  
클라우드 모드에서는 Firestore 관찰을 우선하는 경로가 있다.

## 10. 핵심 비즈니스 규칙 요약

1. **승인 ≠ 이용 완료** — `profileCompleted` 전까지 회원정보 입력 필요  
2. **이름 매칭 upsert** — 기존 엑셀/명단과 계정 연결, 타 계정 충돌 방지  
3. **이메일 초대 예약** — `invitedEmails` + 로그인 시 claim  
4. **휴면 vs 탈퇴** — 휴면은 로그인 차단, 탈퇴는 로그인 허용·모임만 재가입  
5. **강제 탈퇴** — 문서 삭제 + 접근 purge (단순 WITHDRAWN과 구분)  
6. **시스템관리자** — 회원 명단 비등록  
7. **미활동 10분 + 60초 연장** — 금융앱형 자동 로그아웃  
8. **검색 디렉터리** — `meetingDirectory`와 `meetings` 분리  
9. **회비 ↔ 장부** 양방향 동기화  
10. **운영관리자 지정** — 개설자(또는 시스템관리자)만, 해제 후 탈퇴/강제탈퇴 가능

## 12. 배포·운영 유의사항

- Firestore **규칙/인덱스** 변경 시:  
  `firebase deploy --only firestore` (또는 `firestore:rules` / indexes 분리)
- 시스템관리자 이메일은 앱 `SystemAdminConfig`와 `firestore.rules` allowlist를 **동일하게** 유지
- 자격증명·고정 비밀번호 등 시크릿은 본 문서에 평문 기재하지 않음
